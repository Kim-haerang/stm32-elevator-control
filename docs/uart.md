# UART 연동

UART 통신·GUI는 팀원 담당 범위입니다.

## 연결 및 프레임

USART2, 115200 baud, 8 data bits, no parity, 1 stop bit를 사용합니다.

```text
0xAA | LEN | CMD | PAYLOAD... | CHECKSUM
```

`LEN = 1 + payload 길이`이며 CMD를 포함합니다. 체크섬은 LEN·CMD·payload 바이트 합의 하위 8비트입니다. 수신 코드는 LEN이 0이거나 16 이상인 프레임을 거부합니다.

| 명령 | 코드 | 요청 payload | 응답 payload |
| --- | --- | --- | --- |
| 1층 이동 | 0x10 | 01 | 처리 응답 |
| 2층 이동 | 0x11 | 01 | 처리 응답 |
| 3층 이동 | 0x12 | 01 | 처리 응답 |
| UART 비상 설정·해제 | 0x13 | 01 설정 / 00 해제 | 처리 응답 |
| 상태 조회 | 0x14 | 없음 | MOVING, STOP, EMERGENCY 각각 1바이트 |
| 온습도 조회 | 0x20 | 없음 | 온도 정수·소수, 습도 정수·소수 |
| 거리 조회 | 0x30 | 없음 | cm 값 4바이트, 상위 바이트 우선 |

응답 명령은 요청 명령에 0x80을 더한 값입니다. 처리 응답은 `00` 또는 `01`이며, `00`을 실제 층 도착 완료로 해석하면 안 됩니다. 현재 코드는 일부 payload 값에 대한 의미 검증보다 길이 검사를 중심으로 응답합니다.

예: 1층 이동 요청은 `AA 02 10 01 13`, 상태 조회 요청은 `AA 01 14 15`입니다. 이는 코드에서 계산한 프레임이며 실물 송수신 재시험은 진행 전입니다.

온습도 응답은 요청 플래그를 설정한 뒤 메인 루프의 `uart_temp_task()`에서 송신합니다. 다른 일부 응답은 수신 인터럽트 콜백 안에서 블로킹 송신하므로, 모든 UART 처리가 메인 루프에서 실행된다고 설명하면 안 됩니다.
